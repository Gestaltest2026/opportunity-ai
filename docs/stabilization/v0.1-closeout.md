# v0.1 Stabilization Closeout

## Status

Feature work remains paused until deterministic verification is observed passing in a real execution environment.

## Completed architecture work

- Zod is the source of truth for canonical domain schemas and runtime parsing.
- Opportunity availability is canonical; derived databank status is not persisted.
- Databank and Source Registry I/O are isolated behind dedicated I/O modules.
- Structured LLM calls share one boundary for transport, JSON parsing, schema parsing, and error normalization.
- Fixture and ground-truth data are schema-validated.
- LLM verification is separated from deterministic verification.
- Legacy persisted `status` and `source_hash` compatibility state has been removed.
- ADRs record the major architecture decisions.

## Deterministic verification surface

`npm run verify` must pass and currently covers:

1. TypeScript typecheck
2. Semantic hash regression
3. Databank schema regression
4. Fixture schema validation
5. Pure domain regression

## External / nondeterministic verification

`npm run verify:llm` is intentionally non-blocking and should run manually, on a schedule, or before release. It is not a required push/PR gate.

## Re-enable Feature Mode only when

- `npm install` succeeds in a clean environment.
- `npm run verify` succeeds in that environment.
- Any failures are fixed without weakening schemas or regression assertions merely to make CI green.

After those conditions are met, v0.1 Stabilization can be considered closed and feature development may resume.
